Match Each Test Method to the Question It Answers

More test columns do not automatically mean more confidence. Each method needs a defined question, a test condition and an acceptance rule before its data can support a release decision.

Test capability matrix: what each method demonstrates, the conditions it needs and its applicable boundary.

Buyer check before accepting a result

  • Is the product and revision the one you are approving?
  • Do the test conditions match the specification?
  • Is the acceptance limit stated with units?
  • Does the reported lot or serial match the delivered hardware?
  • Is a deviation identified, or is it hidden inside an average?

The sample report used in a review is redacted. Field labels and blank values are intentional; no customer name, fabricated curve or invented measurement is added to illustrate the format.

Define Test Coverage and Equipment Status before Release

Coverage is a project definition: which characteristics, at which stage, on how many samples, with which method and record. It should be written before production starts, not reconstructed from a shipment.

Verification coverage matrix by stage; the final parameters, samples and reviewers come from the product control plan.
StageParameters in scopeSample or coverageMethod and recordResponsible review point

100% needs a subject. SONNE can apply 100% verification only where the specific product and measurement requirement support that statement. It is not a claim that every product, every parameter or every reliability test receives 100% coverage.

Equipment status: Audit fields include equipment identity, applicable method, status and validity information. Only real records are referenced in a project review; missing or unavailable items are not filled with assumed certificate numbers.

Trace Test Results to Lots, Revisions and Corrective Actions

When a result is questioned, the first useful question is which product, revision and lot produced it. Traceability makes that answer retrievable without relying on a folder name or an individual's memory.

  1. Product / lotProject or product ID, lot or serial where applicable.
  2. RevisionDrawing and BOM version used for build and test.
  3. Test recordConditions, method, result and acceptance decision.
  4. DispositionDeviation, containment, correction and retest status.

Nonconformance record fields

Record the discovery condition, affected scope, containment or quarantine status, preliminary review, responsible role and retest result. A corrective-action timeline is agreed for the specific case; no universal response time is promised.

If systemic correction is required, an 8D structure can organize the problem description, containment, root cause, corrective and preventive action and verification. Whether an 8D is opened, and in what format it is delivered, is confirmed for the project.

Change linkage: Design, process or test-method changes connect to the ECN and the affected revision. Later results must use the correct version; see the NPI change-control path.

RF Testing and Quality Evidence FAQs

How to read a PIM result, what coverage means, which fields a VNA report needs, how test data is traced and how to request a sample report.

How should I read a PIM test report?

Read the PIM result together with the product identity, frequency or band, test power, port and connection configuration, measurement units, limit and test conditions. Check whether the reported result corresponds to the required sample or lot and acceptance criterion. A single dBc value without those conditions is not enough for a meaningful comparison or approval decision.

What is SONNE's RF test coverage?

Test coverage is defined by the product, critical characteristics, agreed specification and production stage. SONNE identifies critical RF testing and can apply 100% verification only where the specific product and measurement requirement support that statement. It should not be interpreted as 100% coverage of every test on every product. Confirm the coverage matrix during project review.

What information should a VNA test report include?

A useful VNA report should identify the product and revision, relevant lot or serial information where applicable, ports, frequency range, measured S-parameters, test settings and applicable calibration status. It should also show limits, units, curves or numerical results and the acceptance decision. The exact report content and supplied data format should be agreed for the project.

How are RF test results traced to production records?

Traceability should link the test record to the product or project, applicable lot or serial identifier, drawing or BOM revision, production and test stage, and any deviation disposition. The required depth depends on the product and agreed control plan. During supplier review, buyers can request evidence showing those links rather than relying on an isolated curve or summary value.

Can I request a sample RF test report before placing an order?

You can request a sample test report to review the evidence format and discuss the fields needed for your project. Identify the product type and test method, such as VNA or PIM, so the request can be directed appropriately. A sample is illustrative only; actual measurements, coverage, traceability and report deliverables must be confirmed for your product and specification.

A sample report shows the evidence format only. It does not represent measurements for your product or establish the report package you will receive.
